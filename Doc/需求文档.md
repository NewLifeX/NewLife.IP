# NewLife.IP需求文档

> 版本：v1.0 | 日期：2026-08-04

本文档描述 NewLife.IP 的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

## 1. 背景与愿景

### 1.1 系统定位

高性能、跨平台的 **IPv4 归属地查询类库**，支持**本地离线**与**在线 API** 两种数据源，由用户按需选择。本地模式通过内存映射文件（MemoryMappedFile, MMF）直接对压缩解包后的原始数据库文件进行二分检索，避免整表加载造成的托管内存压力，适合服务端与高并发场景；在线模式调用第三方 Web API 获取归属地，适合数据新鲜度要求高、低频查询场景。作为 .NET 生态组件，可开箱即用地嵌入日志标注、安全风控、网关等应用，并可通过 `IpResolver.Register()` 无缝接入 `NewLife.Net` 生态的统一解析。

### 1.2 愿景

成为 .NET 生态中最轻量、最高效的 IP 归属地查询组件——**本地离线秒回、在线可选兜底**，一句代码完成 IP 定位，零第三方运行时依赖，自动维护数据文件，无缝融入 NewLife 生态的日志 / 风控 / 网关场景。

## 2. 核心目标

| 编号 | 目标 | 所属层级 | 一句话描述 |
|------|------|----------|------------|
| CONV | IP 地址转换 | 基础层 | 提供 IP / UInt32 / 字符串互转的便捷扩展方法 |
| CORE | 核心解析引擎 | 核心层 | 基于 MMF + 二分检索的高效数据库解析，O(log N) 查询 |
| API | 高层查询封装 | 应用层 | 提供开箱即用的 `Ip` 查询对象、数据文件定位与自动下载更新 |
| INT | 生态集成 | 应用层 | 注册为 `NewLife.Net` 统一 IP 解析器 |
| ONL | 在线 IP 对接 | 应用层 | 调用在线 API 查询归属地，用户按需选择离线 / 在线数据源 |

## 3. 功能需求

### 3.1 CONV — IP 地址转换

- **CONV-1 IPAddress↔UInt32 互转**：`IPAddress.ToUInt32()` 与 `UInt32.ToAddress()` 大端整数互转扩展方法。
- **CONV-2 IP 字符串↔UInt32 互转**：`String.ToUInt32IP()` 与 `UInt32.ToStringIP()`（补零格式）互转扩展方法。

### 3.2 CORE — 核心解析引擎

- **CORE-1 索引结构**：定义索引区记录结构 `IndexInfo`（Start / End / Offset）。
- **CORE-2 数据库文件加载**：`IpDatabase.SetFile()` 支持 `.gz` 自动解压到临时文件、MMF 映射与头部解析，暴露 Start / End / Count。
- **CORE-3 二分检索查询**：`IpDatabase.GetAddress(UInt32)` 在索引区二分查找 IP 区间，按标记字节解析重定向，GB2312 解码区域与运营商文本。
- **CORE-4 索引遍历**：`IpDatabase.GetIndex(UInt32)` 按索引位置读取记录，供全库遍历 / 校验使用。
- **CORE-5 多数据源适配**：新增 `IpCsv` 转换器，将 DB-IP 免费 CSV 数据转换为纯真兼容数据库文件，复用现有解析引擎实现多数据源支持（竞品分析 P1 建议）。

### 3.3 API — 高层查询封装

- **API-1 数据文件定位与自动下载更新**：`Ip` 懒加载初始化（双重检查 + 锁），本地文件缺失 / 过小 / 过期时自动从 `Setting.PluginServer` 下载并重建。
- **API-2 字符串 IP 查询**：`Ip.GetAddress(String)` 返回 `(area, addr)` 二元组。
- **API-3 IPAddress 查询**：`Ip.GetAddress(IPAddress)` 返回拼接字符串。

### 3.4 INT — 生态集成

- **INT-1 解析器注册与实现**：`IpResolver` 实现 `NewLife.Net.IIPResolver`，`Register()` 注册到 `NetHelper.IpResolver` 供生态统一解析。

### 3.5 ONL — 在线 IP 对接

- **ONL-1 在线 IP 解析器**：`OnlineIp` 调用在线 API（默认 ip-api.com，免费无 Key）查询 IP 归属地，支持 API 地址与超时可配置，网络失败 / 限流容错返回空。
- **ONL-2 数据源选择机制**：`IpResolver` 支持离线 / 在线模式切换（`Online` 属性），用户按需选择数据源，默认离线保持现有行为。
- **ONL-3 在线查询缓存**：在线查询结果缓存（`MemoryCache`），避免重复请求与触发限流，缓存过期可配置。

## 4. 🧊 暂缓清单

| 功能 | 暂缓理由 | 解冻前提 |
|------|----------|----------|
| IPv6 支持 | 当前专注 IPv4 | 出现公开高质量 IPv6 精细地理数据源 |
| 增量更新机制 | 当前整包下载已够用 | 数据文件体积显著增大或用户明确诉求 |
| Benchmark 基准数据 | 未内置基准测试 | 社区 PR 补充或发版需求 |
| 更精细运营商 / 骨干网识别 | 依赖数据源精度 | 数据源支持 |
| 多在线 API 自动切换 | 默认 ip-api.com 已满足 | 用户明确诉求或免费额度不足 |
| 国内厂商 IP 对接（腾讯/高德/百度） | 需用户申请各厂商 Key，响应结构各不相同；淘宝 IP 库已停服（实测 301→404） | 用户申请 Key 且有明确诉求（优先腾讯位置服务，含省市区县 + 运营商） |

## 5. 不做什么

- **不内置 IP 数据库**：依赖外部纯真兼容格式数据文件（用户自备或首次自动下载），保证组件体积与数据可更新性。
- **不做 IPv6**：暂无高质量数据源，避免半成品体验。
- **不做前端界面**：纯类库，无 UI / Web 管理后台。
- **不做整表内存缓存**：MMF 已足够轻量，避免不必要的托管内存占用。
- **不引入额外第三方依赖**：仅依赖 `NewLife.Core`（含 `NewLife.Net` 解析器接口）。
