## 3. 在线库 vs 本项目 差距分析

- 在线库的**字段丰富度**（ASN/时区/经纬度/风险情报）仍领先，但代价是**网络延迟、配额限制、数据外发与持续成本**
- 本项目在**延迟（微秒 vs 毫秒）、吞吐（无配额）、隐私（数据不出本机）、成本（零持续费用）、离线可用**五个维度全面占优
- **融合方案已落地（ONL 模块）**：`IpResolver.Online = true` 一键切换到在线 API（默认 ip-api.com，含 MemoryCache 缓存与容错），兼顾性能与字段丰富度
- 在线查询失败返回空并写日志，不阻断业务；离线 / 在线可按需自由切换，默认离线保持现有行为

## 4. API 易用性对比（代码示例）

```csharp
// ip-api.com（REST，无 Key）
var json = await new HttpClient().GetStringAsync("http://ip-api.com/json/8.8.8.8");

// ipinfo.io（官方 C# SDK，需 Token）
var client = new IPinfoClient.Builder().AccessToken("TOKEN").Build();
var response = client.IPApi.GetDetails("8.8.8.8");

// NewLife.IP（离线静态库，一行，无网络）
var geo = "8.8.8.8".IPToAddress();

// NewLife.IP（在线模式，切换后同样一行）
IpResolver.Online = true;
var geo2 = "8.8.8.8".IPToAddress();
```

> 在线库代码本身不复杂，但需**申请 Key / 处理限流 / 网络异常 / 配额成本**；本项目在线模式内置缓存与容错，切换成本最低。

## 5. 结论

| 场景 | 推荐方案 |
|------|----------|
| 服务端日志标注 / 网关 / 风控（高并发、低延迟） | **NewLife.IP 离线模式**（默认） |
| 内网 / 离线 / 数据不外发部署 | **NewLife.IP 离线模式**（唯一可行） |
| 低频查询、数据新鲜度优先 | **NewLife.IP 在线模式**（`IpResolver.Online=true`） |
| 需要 ASN/风险情报等丰富字段 | ipinfo.io / MaxMind Web / IPIP.net |
| 中国境内商业级精度 | IPIP.net / 本项目（纯真数据源） |
| 零成本免费小流量 | **NewLife.IP 在线模式**（ip-api.com 内置） |
