# NewLife.IP 竞品分析报告

> 版本：v1.0 | 日期：2026-08-04

## 1. 概述

本报告对比 NewLife.IP 与市面上主流 IP 归属地定位方案，覆盖**静态库**（本地离线数据库）与**在线库**（Web API）两大方向，从功能覆盖、性能、依赖、许可等维度进行综合评估。

NewLife.IP 定位为**高性能本地 IPv4 归属地查询类库**（MMF + 二分检索，纯真兼容格式），属于静态库阵营；在线库作为其可选的补充方案一并分析。

> 数据来源：GitHub API（2026-08-04 采集）、NuGet Search API（2026-08-04 采集）、官网公开信息、ip-api.com 免费接口实测。

## 3. 静态库 vs 在线库 核心对比

> 本表回答"该选静态库还是在线库"，是本次分析的重点。

| 维度 | 静态库（NewLife.IP / ip2region 等） | 在线库（ip-api / ipinfo 等） |
|------|-------------------------------------|------------------------------|
| **部署形态** | 随应用部署，本地文件 + 本地代码 | 远程 HTTP API，需网络 |
| **查询延迟** | 微秒级（二分 ~18 次比较 / MMF 零拷贝） | 毫秒级 ~ 数百毫秒（网络 RTT 主导） |
| **可用性** | 完全本地，无外部依赖 | 依赖第三方服务 SLA，宕机/限流即不可用 |
| **隐私/合规** | 数据不出本机，无外发 | 每次查询将 IP 外发第三方，有隐私风险 |
| **吞吐能力** | 单机高并发，只读线程安全 | 受 API 配额限制（45 次/分 ~ 5 万次/月） |
| **成本** | 一次性数据成本（多数免费/MIT） | 高频查询按量付费，免费额度低 |
| **数据新鲜度** | 依赖手动/自动更新数据文件 | 服务端维护，始终最新 |
| **数据字段丰富度** | 通常仅区域+运营商（本项目） | 丰富：ASN/时区/经纬度/公司/隐私风险 |
| **离线场景** | ✅ 完全支持（内网/离线部署） | ❌ 不可用 |
| **适用场景** | 服务端日志标注、网关、风控、批量离线处理 | 低频查询、需要丰富字段、免维护 |

**结论**：静态库适合**高并发、低延迟、离线/内网、数据不外发**的服务端场景——这正是 NewLife.IP 的定位；在线库适合**低频、字段丰富、免维护**的场景，可作为补充而非替代。

## 6. 结论与建议

### 6.1 本项目优势领域

- **极轻量**：零第三方运行时依赖（仅 NewLife.Core），纯托管，MMF 避免整表内存加载
- **高吞吐**：只读 + ThreadStatic 缓冲，并发安全，微秒级查询
- **离线可用**：完全本地化，适合内网/离线/数据不外发场景
- **生态集成**：`IpResolver.Register()` 一键接入 NewLife.Net 统一解析
- **数据自主**：纯真兼容格式，用户可自备数据文件，自动下载更新

### 6.2 差距领域与追赶优先级

| 优先级 | 差距 | 说明 | 建议 |
|:------:|------|------|------|
| P1 | 数据源单一（纯真） | 精度/更新依赖纯真数据源 | 增加 DB-IP 免费 CSV 等备选数据源适配（格式转换层） |
| P1 | 在线库字段丰富度 | 无 ASN/时区/经纬度等字段 | 评估在 `IpResolver` 上层提供可选增强（不与"轻量"愿景冲突） |
| P2 | IPv6 缺失 | 明确列为暂缓 | 待高质量数据源出现后按暂缓清单解冻 |
| P2 | 增量更新 | 当前整包下载 | 数据文件增大后评估差分更新 |
| P3 | 生态知名度 | MaxMind 下载量 30.9M vs 本项目 82k | 文档/示例/Benchmark 完善，吸引社区 |

> 差距分析不盲目追齐竞品：本项目的"轻量、离线、高吞吐"定位与 MaxMind 的"字段丰富、全球权威"是差异化路线，应优先补数据源多样性与文档生态，而非堆砌字段。
